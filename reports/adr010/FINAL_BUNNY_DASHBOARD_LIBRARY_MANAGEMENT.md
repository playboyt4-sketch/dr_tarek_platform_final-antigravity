## 2. ما هو موجود بالضبط (تدقيق الكود)

### 2.1 طبقة البيانات (سقالة غير مرئية)

`dashboard/lib/features/students/domain/bunny_library_catalog.dart`

هذا الملف — بحسب تعليقه العلوي الحرفي — `NONVISUAL SCAFFOLDING ONLY`:

- يعرّف `BunnyLibraryOption` (‏`id` + اسم عرض + أعلام توفر) — بيانات غير سرية فقط.
- يعرّف حالة الاختيار لمصدر واحد: جديد / موجود / legacy.
- **لا يرسم أي واجهة، ولا يغيّر سلوك أي شاشة قائمة.**
- لا يحمل أي مفتاح، ولا أي مادة توقيع، ولا قالب Pull Zone.

### 2.2 بوابة الربط

`dashboard/lib/features/students/data/bunny_association_gateway.dart`

تستدعي الدالتين القابلتين للاستدعاء `validateBunnyVideoAssociation` و`associateBunnyVideoToLibrary` — أي أنها تغطي **الربط** لا **الاختيار**.

### 2.3 شاشة إضافة المصادر (الحالية)

`dashboard/lib/features/students/presentation/widgets/add_lecture_resources.dart`

- النمط الحالي: **Video-ID فقط**. الطبيب يرفع الفيديو إلى Bunny خارج اللوحة ثم يلصق الـGUID.
- `isValidBunnyVideoId` يرفض الروابط ويقبل الـGUID فقط.
- `StagedResource.bunnyLibraryId` يُهيّأ إلى `defaultBunnyLibraryId`، والحقل `libraryReviewRequired` موجود لكنه غير مستخدم لعرض أي عنصر اختيار.
- تعليق الكود نفسه يقول: "No picker is ..." — أي أن الاختيار غير منفَّذ بقرار سابق، لا بنسيان.

### 2.4 الـ backend

`functions/src/index.ts:7802` → `listEligibleBunnyLibraries`

```
await requireContentManager(request);
libraries = await loadEligibleBunnyLibraries(db, {...process.env});
return {libraries};
```

و`loadEligibleBunnyLibraries` في `functions/src/core/video/bunny_library_catalog_reader.ts:142` تفعل شيئاً واحداً فقط:

```
const snapshot = await store.collection("bunny_libraries").get();
```

ثم تُرشّح عبر `selectEligibleBunnyLibraries`:

- تتجاهل أي مستند لا يطابق `document.id === option.libraryId`.
- تُطبّق قائمة منع طارئة من `BUNNY_ACTIVE_LIBRARY_IDS` إن وُجدت.
- تُعيد فقط الحقول غير السرية.

### 2.5 الحالة الحقيقية في Production

فحص قراءة فقط (عدّادات فقط، بلا أي بيانات شخصية):

```
bunny_libraries.count = 0
```

**لا يوجد أي مستند في مجموعة `bunny_libraries`.**

النتيجة الحتمية: `listEligibleBunnyLibraries` تُعيد اليوم قائمة **فارغة** في Production. أي واجهة اختيار تُبنى الآن ستُظهر حالة فراغ دائمة، وهذا ليس عطلاً في الواجهة بل غياب كتالوج.

## 3. سبب الحجب الأول — تعارض معماري مع قرار Option 1

Mission 23 اختار **Option 1** صراحةً:

- لا تفعيل لكتالوج `bunny_libraries` في Firestore.
- مسار المكتبة الافتراضية القديم (legacy default) لمكتبة `736742`.
- أسرار عامة واحدة (`BUNNY_STREAM_API_KEY`, `BUNNY_TOKEN_KEY`).
- تقليل سطح التعرض.

لكن اختيار مكتبة من عدة مكتبات يتطلب حتماً **Option 2**:

| عنصر Option 2 | لماذا هو شرط |
|---|---|
| مجموعة `bunny_libraries` في Firestore | هي المصدر الوحيد الذي تقرأه `listEligibleBunnyLibraries` |
| أسرار لكل مكتبة `BUNNY_<ID>_STREAM_API_KEY` / `BUNNY_<ID>_TOKEN_KEY` | بدونه لا يمكن للـ backend التوقيع أو قراءة metadata لمكتبة غير الافتراضية |
| `BUNNY_ACTIVE_LIBRARY_IDS` | قائمة السماح/المنع التي تمنع تفعيل `775315` أو أي مكتبة غير معتمدة |
| `BUNNY_DEFAULT_LIBRARY_ID` | تحديد الافتراضي بشكل صريح بدل الاعتماد على متغير واحد |
| تحقق كتالوج على الخادم | "الخادم هو سلطة الأهلية" — مطلوب أمنياً |
| IAM إضافي لكل سر | مبدأ أقل صلاحية |

**الخلاصة:** لا يمكن تنفيذ "اختيار مكتبة" داخل Option 1 دون تحويله إلى Option 2. وهذا التحويل **ممنوع بدون موافقة صريحة من المالك** (البند 16 من المهمة).

لذلك: هذا المسار **متوقف عند حد القرار**، وليس عند حد القدرة التقنية.

### 3.1 خطة الترحيل المقترحة (للموافقة فقط — غير منفَّذة)

1. إنشاء مستند واحد فقط في `bunny_libraries` للمكتبة `736742`، بالحقول المطابقة لمخطط Mission 8/16 (المعرّف = معرّف المستند).
2. عدم إضافة `775315` إطلاقاً، وعدم إضافتها لقائمة السماح.
3. إبقاء `BUNNY_STREAM_API_KEY` العام كما هو (Option 1) في المرحلة الأولى — أي أن الكتالوج يُستخدم للعرض والتحقق فقط، دون أسرار لكل مكتبة.
4. تفعيل الواجهة، ثم اختبار `listEligibleBunnyLibraries` أنها تُعيد عنصراً واحداً فقط.
5. عند الحاجة لمكتبة ثانية فعلياً: إنشاء `BUNNY_<ID>_*` + توسيع IAM + إضافة المعرّف إلى `BUNNY_ACTIVE_LIBRARY_IDS`.

المرحلة 3 هي الحد الأدنى الذي يفتح الواجهة بأقل تغيير ممكن، لكنها تبقى **تغييراً في قرار Option 1** وتحتاج موافقة.

## 5. متطلبات الأمان التي تم التحقق منها في الكود (جاهزة مسبقاً)

هذه البنود **لا تحتاج تغييراً** — تم التأكد من وجودها:

| المتطلب | الدليل |
|---|---|
| الطالب لا يستطيع الوصول لإدارة المكتبات | `listEligibleBunnyLibraries` تبدأ بـ`requireContentManager(request)` |
| لا مفتاح API في استجابات الشبكة | الـ backend يُعيد `{id, name, availability}` فقط — لا أسرار |
| لا مفتاح Token في حالة العميل | لا يوجد أي مسار يُعيده |
| لا بيانات اعتماد في التخزين المحلي | طبقة الكتالوج لا تكتب أي شيء محلياً |
| لا تفعيل مكتبة عبر طلب عميل | التفعيل من `BUNNY_ACTIVE_LIBRARY_IDS` (بيئة الخادم) فقط |
| رفض المكتبات غير المعروفة/غير النشطة | `selectEligibleBunnyLibraries` تُسقط أي مستند لا يطابق معرّفه أو يكون في قائمة المنع |
| `bunny_library_id` غير قابل للتلاعب من العميل | `firestore.rules` → `lecture_resources`: |
| | `create`: `request.resource.data.get('bunny_library_id', null) == null` |
| | `update`: القيمة الجديدة == القيمة القديمة (غير قابلة للتغيير) |
| مجموعة الكتالوج محجوبة عن العملاء | `bunny_libraries`: رفض كامل لكل وصول من العميل |

هذا يعني أن **الأساس الأمني جاهز**، والمفقود هو الواجهة + الكتالوج.
